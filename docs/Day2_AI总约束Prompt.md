# Day 2 给编程 AI 的总约束 Prompt

你将协助开发"链路实验室"。请先阅读 README.md、docs/需求边界.md、docs/动画白名单.md、docs/工作台草图.md 和 docs/访谈笔记.md。

范围固定：一个虚构校园报名场景、七节点、两条预设路径 A/B、三种防御 D1/D2/D3、两个初始条件 O/T、三种预设 A/B/C、三个页面和七步学习流程。

O/T 是两档吸附滑块：拖动中只预览，松手且值变化才提交，一次拖动最多生成一条运行；松手未变化不创建运行。动画只按规则事件下标表达：未执行时流线消失、请求被拒时撞护栏回弹、模拟数据到达时穿透、D3 告警时出现侧向脉冲且不阻拦主流线。关闭动画后信息不能丢失。

业务结果必须由确定性规则引擎判定，不模拟随机性与概率。默认一句话解释使用规则模板，只生成一次并随运行落库；历史回放只读已保存内容。可选模型 API 不是当前开发任务。

技术栈固定为 React、TypeScript、Vite、React Flow、Node.js、Fastify、SQLite 和 npm workspaces。今天不执行本 Prompt；Day 2 再按当天任务逐步启动开发。

访谈结论已并入需求，请在实现时遵守：

1. 学习者主要卡在"这一步为什么成立"，而不是"有哪些步骤"。因此逐步播放与每步条件说明是核心功能，不是装饰。
2. 三位受访者都能复述三种防御的名词，但讲不清各自改变什么、如何配合。因此必须能清楚区分告警、拒绝与数据到达，三者不可混用同一视觉或文案。
3. 两位受访者强调本工具不能替代实操，只能作为入门引路。因此界面文案不得使用"实战""提升攻防能力""替代靶场"等表述，也不得把沙盘结果写成真实系统安全结论。
4. 受访者提出"看懂之后要自己试、试的时候回头对照"。因此历史回放是学习环节，回放入口需可见、可回放、可核对。

请在修改任何文件前，先列出本阶段的目标、拟修改文件、输入输出、验收方式，以及你发现的需求冲突。不要自行扩展真实攻击、更多场景、自由聊天、流式输出、装饰动画或 3D。
