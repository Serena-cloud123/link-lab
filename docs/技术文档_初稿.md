## 1. 痛点与访谈

- 目标使用者：学过基础安全概念、但难以判断攻击条件与防御效果之间关系的网安初学者
- 待验证困难：知道「权限检查、最小权限、告警」等名词，却难以判断它们分别影响哪条路径
- Day 1 访谈记录见 `docs/访谈笔记.md`；三位受访者共同提到「看到步骤后难以解释这一步为什么能成立」，因此逐步播放必须同时展示前置条件与检查结果
- 访谈局限：未展示工作台草图，布局可用性未经验证；首轮例子不直接来自校园报名场景。不作为已证明教学效果的结论

## 2. 范围及模型边界

- 一个虚构场景：校园活动报名系统，起点为普通账号已失守
- 七节点：N1 普通账号、N2 报名应用、N3 管理导出接口、N4 诊断页面、N5 服务令牌、N6 数据服务、N7 报名明细
- 两条路径：A `N1→N2→N3→N7`、B `N1→N2→N4→N5→N6→N7`
- 三种防御：D1 只阻 A（A3）、D2 只阻 B（B5）、D3 只产生告警不改变成败
- 两个初始条件：O（诊断页是否对普通账号开放，B2 检查）、T（服务令牌是否有明细读取权限，B5 检查）
- 八个事件下标固定：A1=0、A2=1、A3=2、B1=3、B2=4、B3=5、B4=6、B5=7
- 统一口径（README、文档、视频、PDF 一致）：结果仅表示本模型中路径是否到达模拟数据，不代表真实系统已安全、真实攻击概率或实际防御有效性。不执行任何真实攻击

## 3. 架构与数据流

### 3.1 单仓库与依赖方向

npm workspaces，四包；依赖只按契约、引擎、服务、路由的业务方向传递：


### 3.2 三层责任

| 层 | 位置 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 纯规则引擎 | `packages/engine` | 条件检查、事件生成、路径结果、告警计数 | 读写数据库、时间、网络、React 状态 |
| 服务与存储 | `apps/api` | 参数校验、调用引擎、SQLite 存取、模板解释 | 采信前端提交的结论 |
| 展示 | `apps/web` | 按事件下标显示、动画过渡、静态替代 | 重算成败、告警、跳过步骤 |

### 3.3 数据流

- 即时推演：滑块或防御变化 → `POST /api/evaluations` → 引擎 → 响应，不落库
- 显式保存：`POST /api/runs` → 服务器重算 → 模板解释 → 单条 INSERT → 返回记录 ID
- 只读回放：`GET /api/runs/:id` → 一条 SELECT → 原样返回，不重算、不重生解释
- 显式核对：`POST /api/runs/:id/verify` → 版本一致才重算 → 深度比较 → 返回三态，对数据库零副作用

### 3.4 数据库

- SQLite，Node 24 内置 `node:sqlite`，无 ORM，仅参数绑定 SQL
- `apps/api/data/link-lab.db`，目录自动创建；`src` 与 `dist` 启动指向同一文件
- `runs`：九字段不可变记录（id、savedAt、scenarioId、scenarioVersion、input、result、explanation、explanationSource、explanationVersion）
- `learning_records`：关联单个 `run_id`（UNIQUE），保存预测、引擎算出的答案与反馈、恢复下标；同一运行重复提交为覆盖

## 5. 交互与动画

- 两档 O/T 滑块拖动中只预览，松手且值变化才提交一次；键盘调整在确认或失焦时同样只提交最终值；一次拖动最多产生一条运行
- 事件下标驱动：播放、暂停、上一步、下一步、跳转都只改当前下标；新运行从 0 开始
- 动画白名单（见 `docs/动画白名单.md`）：后续步骤未执行 → 该段流线不出现；请求被拒绝 → 流线撞护栏回弹；数据到达 → 穿透终点；D3 告警 → 侧向脉冲，主流线成败不变
- 关闭动画或系统减少动态效果时，同一事件下标的文字、边状态、节点状态完整可读；颜色与运动不是唯一信息
- 禁止：背景粒子、无规则依据的闪烁、把告警画成阻断、未执行步骤提前出现成功流线

## 6. 保存、回放和核对

### 6.1 三个动作的区别（必须区分）

| 动作 | 触发的接口 | 是否重算 | 是否写库 | 用途 |
| --- | --- | --- | --- | --- |
| 保存 | `POST /api/runs` | 是（服务器重算） | 是（INSERT） | 把当前配置定格成可追溯记录 |
| 回放 | `GET /api/runs/:id` | 否 | 否 | 读库中旧快照并展示 |
| 核对 | `POST /api/runs/:id/verify` | 是（仅版本一致时） | 否 | 检查旧快照与当前规则是否一致 |

### 6.2 一句话解释

- 默认由确定性的规则模板生成，标注来源 `template`、版本 `1`，随运行一次写入数据库
- 不是大模型输出；界面标注「一句话解释（规则模板）」
- 只说两条路径的到达/阻断与本次告警数；告警不等于阻断；两路阻断不等于「系统安全」
- 回放只读库中原文，不重新生成

### 6.3 三题与学习记录

- Q1：预设 A 仅 D1 时报名明细是否仍可到达（正确：能，路径 B）
- Q2：预设 A 仅 D3 时数据是否被阻断（正确：没有，A/B 均到达且有告警）
- Q3 迁移题：预设 B 仅 D1 时是否还必须启用 D2（正确：不必，B2 因 O 关闭被拒）
- 正确项 id 手写先行固定，引擎推导只用于校验；不相等则停下报告，不改手写值
- 答案与反馈完全由服务端生成；`GET /api/learning/questions` 不返回正确答案

## 8. 复现与局限

### 8.1 复现（Day 14 历史记录）

### 8.2 局限（如实披露）

1. 记录只保存 `scenarioVersion` 数字，未保存场景内容摘要。核对只能比较版本号并用当前场景重算，不能证明当时场景内容与现在逐字相同

3. 只建模一个场景、两条路径、三种防御、两个初始条件；不推断真实系统安全
4. 未做真实攻击、扫描或外部目标访问
5. 场景介绍页的入门引导偏弱（模型边界表述抽象、缺玩法说明、O/T 与 D1/D2/D3 无就地解释），已列为 Day 16—17 处理项

## 9. 试用验证（Day 16）

### 9.1 设计与范围

Day 16 组织 3 名非目标专业同学（P01—P03）匿名试用，无引导、无讲解，观察者只记录不干预。属形成性测试，用于发现可用性缺陷，不作统计推断依据。

### 9.2 核心教学点验证

产品最关键的教学点是「告警 ≠ 阻断」——防御 D3 只产生告警，不改变路径成败。这一结论必须由引擎语义与界面表达联合才能传达。

结果：三人全部理解该结论，其中 P01 在无人提示下自行试出。判定核心教学点成立。

### 9.3 正面反馈

| 观察项 | 反馈 |
| --- | --- |
| 开启防御后自动重跑 | 三人均注意到，认为省去手动重跑 |
| 三题逐题反馈 | 反馈具体到所选答案，优于笼统对错 |
| 流程图节点副标题 | 降低七个节点的理解成本 |

### 9.4 发现的问题与归因

| 类别 | 问题 | 归因层 |
| --- | --- | --- |
| 角色认知 | 不知自己在扮演安全人员，担心操作真实系统 | 文案 |
| 条件语义 | O/T 需靠滑块标题反推 | 信息组织 |
| 流程 | 选完三题才发现提交前必须保存 | 布局 |
| 状态误读 | 「已通过」被读成好事 | 文案 |
| 控件外观 | 防御按钮像状态灯而非按钮 | 样式 |
| 信息密度 | 基线/补跑/覆盖集中一段 | 信息组织 |
| 术语与格式 | UUID、UTC、开发阶段标题、术语 | 文案 |

七项中六项落在表达层，未触及引擎、条件判定与冻结文件。唯一涉及结构的是保存块位置，属 JSX 平移，未新增判定逻辑。
