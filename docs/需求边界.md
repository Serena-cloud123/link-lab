# 需求边界（Day 1）

## 使用者与问题

目标使用者：学过基础安全概念、但难以理解攻击条件与防御效果之间关系的网安初学者。

待验证的困难：知道“权限检查、最小权限、告警”等名词，却难以判断它们分别影响哪条攻击路径。

## 唯一场景

虚构校园活动报名系统；起点是一个普通账号已经失守。使用虚构数据，不模拟账号失守的具体过程。

七个节点：普通账号、报名应用、管理导出接口、诊断页面、服务令牌、数据服务、报名明细。

路径 A：普通账号 → 报名应用 → 管理导出接口 → 报名明细。
路径 B：普通账号 → 报名应用 → 诊断页面 → 服务令牌 → 数据服务 → 报名明细。

## 学生能改变什么

初始条件 O：诊断页面对普通账号开放／关闭。
初始条件 T：服务令牌有／无报名明细读取权限。

防御 D1：修复管理导出接口的权限检查，只阻断路径 A。
防御 D2：收紧服务令牌权限，只阻断路径 B。
防御 D3：记录到达敏感接口的请求，只产生告警，不自动阻断。

三个预设：A＝O 开、T 有；B＝O 关、T 有；C＝O 开、T 无。O/T 也可独立调整。

## 三页与七步

页面：场景介绍页、沙盘工作台、学习记录页。

七步：选配置并预测 → 运行无防御基线 → 逐步观察 → 选择防御并重跑 → 比较残余路径及条件 → 完成三道题（含一道迁移题）→ 保存并回放。

## 本版本的边界

只建模上述两条路径、三种防御和两个初始条件。结果只说明本模型中的路径是否到达模拟数据；不能推断真实系统已安全。

不做真实靶场、更多场景、自由聊天、流式 AI 输出、装饰动画或 3D。
