### 「无变化应为 0 次」在键盘下无法构造，属已知实现差异

- 每次方向键 keyup 都提交一次；提交后滑块在运行期间被 disabled，焦点被移到 body，同一次聚焦内无法再按第二下。因此「按左再按右回到原值」实际是两次独立提交，不是一次会话内的往返。
- 真正的 0 次 no-op 只在鼠标拖出再拖回原位时成立（实测 0 条）。
- 附带观察：不等请求返回时快速连按，只有 1 条 POST，且反向那一下被 disabled 中的滑块吞掉，值停在第一档。UI 显示值与实际提交值一致，不产生状态错乱。
- 处理：本轮不改。判据是「可观察行为不产生错误结果」；改动涉及 Day 9 的键盘提交时机，牵动一批既有测试，风险大于收益。

## 浏览器发现的问题与修复

### 问题 1（已修复）：系统「减少动态效果」被本地动画偏好覆盖

- 复现：页面动画开关为「开」（localStorage 已存 `"true"`），Windows 已开启「减少动画效果」。刷新后播放流线、拒绝回弹、D3 侧向脉冲、N7 到达穿透全部照常播放，实测 `flowPassed` / `alertPulse` / `flowDataArrived` 均处于 running。清掉 localStorage 再刷新（系统仍 reduce）时开关自动变「关」，无动画，静态徽标与文字仍在。
- 根因：`App.tsx` 的 `animationsEnabled` 初始化先读 localStorage，命中即返回，不再查 `matchMedia("(prefers-reduced-motion: reduce)")`；`styles.css` 无 `@media (prefers-reduced-motion: reduce)` 兜底，动画完全依赖 `.animations-enabled` 单类控制，JS 判错时 CSS 无法挽救。
- 修复：抽出 `resolveAnimationsEnabled()`，系统偏好无条件优先，`matchMedia` 的 change 回调复用同一函数；新增 `systemReducesMotion` state 在系统 reduce 期间禁用动画开关；`styles.css` 追加 media query 兜底，只针对 `.flow-overlay-path`、`.alert-pulse-overlay`、`.arrived-pulse-overlay::before` 三个纯运动层，静态边色、徽标、文字、条件理由不在规则内。
- 修复验证：四种情形实测通过（系统 reduce 时强制关并置灰、清 localStorage 后仍关、系统偏好解除后动画恢复、手动关闭的偏好不被覆盖）。回归测试新增一条：mock `matchMedia` 返回 `matches: true` 且 localStorage 为 `"true"`，断言图容器不含 `animations-enabled` 类，且 `.graph-node-alert-badge` 存在于 DOM。
- 提交：`bb1485b`
