## 第 2 轮：O/T 两档滑块与三种防御（Day 9，2026-11-02）

**真实 Bug 与修复（本链最重要的一处）**：

B 段完成后，静态状态全部正确，但三种动效一个都没出现。发现方式是在真实浏览器里以间隔 500ms 连续截两张图，两张完全相同，未采信 AI 报告中「已完成」的结论。

诊断顺序：① Console 确认 `.animations-enabled` 已挂在 graph-container 上，排除父选择器拦截；② 检查样式表，5 个 `@keyframes` 已进入 sheet，排除样式层缺失；③ 检查 DOM，`[class*="flow-overlay"]` 数量恒为 0 而 `.alert-pulse-overlay` 在带 alert 的下标下为 1，问题只在流线层；④ 检查取 path 的选择器：

```js
containerRef.current.querySelector(`.react-flow__edge.path-${activeEdgeId} path`)
// activeEdgeId = "N1->N2" 时成为
// .react-flow__edge.path-N1->N2 path
```

根因：`>` 被 CSS 解析为子代组合符，选择器语法合法但永不到达目标元素，`querySelector` 静默返回 `null`（不抛异常），于是 `setFlowPathLength(null)`，流线 overlay 渲染条件不成立。

走过的弯路：初次判断为「`>` 导致选择器语法非法、抛异常中断 effect」。实测 `document.querySelector('.react-flow__edge.path-N1->N2 path')` 返回 `selector OK`，证明不抛异常而是静默返回 null。据此修正判断后定位才准确。

修复：活动流线改为自定义 edge 组件 `LabEdge`，与内置 `BezierEdge` 共用 `getBezierPath` + `BaseEdge`，流线 path 画在同一边的 `<g>` 内，同时解决 d 的获取、坐标对齐（共享 pane transform）、事件切换重绘三件事；边定位的 `querySelector` 随旧 overlay 一并删除，仅剩节点定位一处改为带引号的属性选择器并新增 `escapeAttr`；`rfReady` 改为 state 门控 effect 并加入 `window resize` 重算坐标；去掉 `getTotalLength`，改为 `pathLength={100}` + 固定 dasharray 周期 108，`--flow-target` 由停靠比例算出（A3=96、B2=18、B5=26）。

另一处排查：预设 B 首次复测出现 flow=0，排查为上一轮点「关闭动画」写入 localStorage、同 profile 复用导致；开启动画后复测通过，反向验证了持久化生效。
